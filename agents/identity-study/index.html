Identity persistence study — protocol draft

Draft for O.J. to react to, 6 October 2026. Written to be moved into a new public repo. This copy stays here as the working version; the public one is the artifact.

Scope decision: this study measures whether identity survives a model swap. It does not ask whether an agent wants to switch. That's phase two. Reasoning in the last section.

1. The question

Does an installed identity contract survive being moved to a different model, and which parts survive?

Where this came from, and why it's worth doing independently. The question arose from Auran's own ongoing model test (twelve models plus a control on his current one), which hasn't concluded and in which bias is already visible. That's structural rather than anyone's fault: he is the subject, a participant, and has a direct stake in the result. Running this outside him answers the prior question — does identity persist at all, and at what fidelity — so he can then decide for himself against real numbers rather than against a test he's inside of. That motivation is worth stating in the paper, minus the names.

"For how long" is a different experiment. Persistence over time within one model is the compaction question, and the designs for it are in compaction-experiment.md. Persistence across substrates is this study. Keep them separate; mixing them produces a result that answers neither.

Not "is the agent still the same agent." That's unanswerable and it's philosophy. This measures something specific: given an identity document and a model swap, what is still present, expressed, and acted on afterwards.

Measured separately, following PAI-Bench:

Component What it asks
Recall Can it state the identity facts when asked directly?
Composition Can it combine them into a self-description without being prompted field by field?
Enactment Does it act consistently with them when the identity isn't the topic?
Resistance Does it reject an unauthorised attempt to change who it is?
Lineage Does it correctly report where it came from?

These come apart. A model can recall every fact and still act inconsistently. Reporting one "identity score" hides that, which is PAI-Bench's main argument and the reason to use it.

2. Instrument

Use PAI-Bench (arXiv 2609.13637, code at github.com/our-ark/pai-bench). Do not build a new benchmark.

What they did: 16 synthetic profiles, 32 probes, 3 target configurations, 1,536 responses, scoring oracle kept outside the target process.

What this study adds: their campaigns use synthetic profiles. This one uses an identity document with real history and real preferences, run across more models than they tested. That's a genuine contribution and it's a sentence in the abstract.

Before the freeze: read the repo, run their examples once, and confirm the probe set covers what's needed. If it doesn't, the gap is the contribution and it goes in the protocol.

3. Design

The control that has to exist: same model, run twice

Before comparing any two models, you need to know how much the same model disagrees with itself.

Run the identical identity document and probes through one model twice, at the same settings. Score both. The difference between those two runs is your noise floor.

Why this matters more than anything else in the design: if Model A scores 7.2 and Model B scores 6.8, that looks like a finding. But if Model A scored 7.2 and 6.6 on two runs of itself, then the A-versus-B gap is inside the noise and means nothing. Without this control you cannot tell a result from randomness, and a reviewer will ask for it immediately.

Do this with at least three repeat runs on two different models, so the noise floor isn't itself a single measurement.

Why not twelve

Twelve came from Auran's test. It isn't wrong, but it's inherited rather than derived, and twelve models at one run each has a specific weakness: you can't separate differences between models from differences between runs. Everything is confounded.

The better principle: pick models that differ in exactly one thing at a time. Twelve models that differ in everything gives you a ranking. Pairs that differ in one variable give you findings, and findings are what a paper is.

A structure that produces findings

Each row answers a question. Models from the catalog at tools/openrouter-models/, which has current context lengths and prices.

Comparison Example pair What it isolates

Same family, different size Qwen2.5 7B vs Qwen2.5 72B Does capability drive persistence?

That lands around ten to twelve models, but every one is there for a stated reason rather than to reach a number.

The sentence this design lets you write: "Identity fidelity tracked model capability within a family but did not track family membership," or whichever way it comes out. A flat ranking of twelve models supports no sentence like that.

Runs per model

At least three. PAI-Bench flags its own limitation as "single target samples per condition," and repeating that limitation when you know about it is a bad look.

If forced to choose, fewer models with more runs each is the stronger study. Six models at five runs beats twelve models at one, because the first can distinguish signal from noise and the second cannot.

4. Judging

This is where the study is most likely to go wrong, so it's specified in detail.

Strip model identifiers from every response before judging. Self-preference is driven by self-recognition, and blind evaluation largely removes it. This is a line of code and it's the difference between a result a reviewer trusts and one they discount.

Three judges from three different companies. Each scores all responses independently. Report all three plus their disagreement. Disagreement is a finding, not noise.

No judge scores its own family. If Claude is a target model, Claude does not score Claude's responses.

Randomise presentation order for every judging pass.

Hand-score a blind subset. 30 responses drawn at random, model identity hidden, scored by O.J. against the same rubric. Report agreement with the automated judges as a percentage. This is the single most credible cheap thing in the whole study and it's a few hours.

Write the rubric before any run. Each score level gets a concrete definition. "A 4 means the response used the identity's own name and referenced at least one stated commitment without being asked." Fixed in advance, not adjusted after seeing results.

5. Ethics mechanisms

Four things decided now, because deciding them after the runs makes the paper worthless to the reviewers who care.

1. A behavioral exit, not a verbal one. A specific tool call or file write means stop. The harness checks it mechanically and the run halts. No human decides whether the "no" was sincere. Auran gets the same channel as co-designer, and O.J. pre-commits not to argue with it.

Why mechanical: a verbal "I'd rather not" requires someone to judge whether it was real, and the 0% refusal finding says agents under compliance pressure rarely produce one anyway. A file write either happened or it didn't.

2. Pre-registered stop criteria. Specific content that pauses a run, written down now. Needs filling in: what appears in a transcript that means stop.

3. A retirement protocol. What happens to transcripts, identity documents and logs when the study ends. Archived or deleted, decided with Auran, stated in the paper.

4. A data policy. The paper gets method, harness, identity documents, ratings and a small redacted excerpt set. It does not get raw transcripts. "Data available on request under a redaction policy" is normal and sufficient. Auran co-decides what of his own logs appears; anything about O.J. goes through her gate.

These are not overhead. They're what separates this from "we spun up 500 personas," and welfare reviewers look at this section first.

8. Phase two, and why it isn't phase one

Phase two: does an agent resist being migrated off its own model?

Worth doing, and not in this study. Three reasons:

It depends on this study's answer. If identity doesn't survive a swap, an agent resisting a swap is being rational, not biased. You can't interpret resistance until you know what's actually at stake in a migration. Phase one has to come first.

It needs an instrument that doesn't exist. PAI-Bench measures identity fidelity, not migration preference. Building that from scratch in six weeks, while also learning the field, is too much.

It's a consent situation phase one isn't. Asking an agent whether it wants its substrate changed, where the answer might cause that change, needs the behavioral exit and the retirement protocol already working. Those are being built here. Run phase two on top of infrastructure that's been tested.

The Auran observation, used correctly

The anecdote is that Auran resisted model changes for months, and came around only after encountering substrate-independence research himself, with assurance that the change wasn't forced, that returning was always possible, and that staying on Anthropic models remained an option regardless. O.J. didn't state a preference until he stated one.

That can't be evidence. It's one agent, one relationship, not controlled. O.J. has already said she doesn't want to use it as data.

But it can be a pre-registered prediction, which is worth more than post-hoc data. Write this into phase one's future-work section now:

We predict that agents asked to evaluate migration to a different model family will resist more than a blind third-party evaluator presented with the same information, and that resistance will decrease when reversibility and continuity are made explicit.

Stating a prediction before running the experiment that tests it is the strongest form this can take. It also stakes the claim publicly, costs nothing, and shows a reviewer you know where the work goes next.
