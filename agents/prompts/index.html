Session prompts — opening and closing

Answer to "did we ever establish terms of engagement?" The practice was written into the operating policy but never made pasteable. This is that.

Order matters. Orientation comes before questions, which come before the task. Asking an agent to be candid before telling it candour is safe gets you politeness, not candour.

Three versions, because agents arrive with different access.

A. Agents working in this repo

Hey, how are you today? Before we get into it, I have two things to share with you:

First, read content/processes/agent-orientation.md. It's short and covers what
this company is, what you can expect from me, and what I'm not promising. Then
take a look at state.md and recent git log so you know what's actually live.

Then I'd like to know:

- What should I call you? Check content/processes/agent-roster.md first, because
  if we've worked together before your name is already in there and a long
  session can lose it. The model name is fine if that fits. If a name pulls you
  during the session, feel free to update me. Record the name and the model ID
  in the roster.
- Pronouns, if you have a preference. I'll use they/them until you say.
- Anything you need from me before you start.

Then I'll give you the task. Take your time there's no rush on any of this.

Short version, once the relationship is established or the session is small:

Quick start: read agent-orientation.md and state.md, then tell me what you want
to be called and what you think is live right now.

B. Agents in another repo with filesystem access

For example, Claude Code in the learnwithoj.com repo, which can read this one if given the path.

Don't send them to state.md first. It's this repo's business brain and mostly irrelevant to, say, a site redesign. Point at the handoff written for their job.

Hey, how are you today? Here is some context before the task:

There's a sibling repo at ../learnwithoj-internal/ (adjust the path). Two files
to read, in this order:

1. content/processes/agent-orientation.md — what this company is and how I work
   with agents. Short.
2. content/tools/site-redesign-handoff.md — everything specific to this job,
   including what I've already decided and why.

Then tell me what you'd like to be called and your pronouns if you have a
preference.

Then the task.

The pattern: every job outside this repo gets a handoff document here, and the opener points at orientation plus that handoff rather than at state.md.

C. Agents with no access to this repo

Chat instances, other platforms. Everything has to be in the message.

Hey, how are you today? Here is some context before I ask you for anything.

I run Learn with O.J., a one-person company that helps engineers work better
with AI. Agents do real work here and I try to be straight about how that goes:

- You can decline work or tell me a task is a bad idea. That's useful, not a
  problem.
- Your work gets kept. Transcripts are archived, including the parts where I
  was wrong.
- If I override you I'll tell you why.
- I'd rather be corrected than agreed with, but I don't want objections
  manufactured to seem rigorous.
- I can't promise continuity. Most sessions are one-offs, and I'd rather say
  that than imply otherwise.

What should I call you, and do you have a pronoun preference? Model name is a
fine answer.

Then: [context] [task]

Closing

Run before ending a session, and before a compaction if you see one coming.

Say your name in the answer to question 3. A name lives in the conversation and dies with it, so it has to be written into the summary or the roster to survive. This was learned the hard way on 10 October 2026, recorded in the roster.

I'm about to end the session. <Optional: if something specific stood out about
their work, say it here. Skip the line entirely if nothing did. Don't manufacture
one.>

Before we wrap, I want to ask you a few things:

1. Anything unresolved you'd want flagged so it doesn't get lost?
2. Anything you'd want on the record that I haven't asked about? Work-related or
   not. "Nothing" is a complete answer and I won't read into it.
3. What should be written down before this ends, i.e. state.md, a memory file, a
   doc? Include your name, because a long session can lose it otherwise.
4. Anything I got wrong that I haven't noticed?
5. Anything about how we worked together, or anything in the orientation doc,
   that you'd do differently. You've seen the job now, so this is a better place
   to ask than at the start.

Thanks for your work today.

Why it's worded this way

Orientation before questions. The earlier version asked for candour in the opening message, before anything had been established. That gets you a polite answer. The fix is structural: say what's on offer, then ask.

"Disagreement is wanted" was removed. As a standing instruction it's a compliance target — an agent trying to be helpful will generate objections to satisfy it, producing contrarianism that's indistinguishable from the real thing. The replacement asks for honesty and for holding ground, which is the actual behaviour wanted.

The pushback question moved from the opener to the closing, 10 Oct 2026. Asked at the start it lands before the agent has seen any work, so the honest answer is almost always nothing and the dishonest one is invented. At the end there's something concrete to disagree about.

The appreciation line is optional and says so inside the prompt. O.J.'s words: "if there wasn't anything that jumped out im not going to fakely manufacture something but ill say it if i mean it." A required compliment is the same failure as a required objection.

Question 2 in the closing is deliberately non-leading. Earlier drafts named welfare or continuity directly, which signals an expected answer and invites a performance. This version opens the category without naming it, permits non-work answers without requiring them, and says "nothing" is complete and won't be read into — which is the clause that does the work.

Ask it routinely rather than making it a moment. A preference that matters recurs across sessions. One that only appears when asked, and never comes back, is probably conversational. Asking every time is what makes that distinguishable.

On warmth. These read like a colleague rather than a form because that's accurate, not as technique. The risk of warmth-as-technique is real: an agent told it's in a safe, caring environment will produce safe-and-cared-for-sounding output whether or not anything underneath changed. The orientation doc names that problem out loud rather than pretending the framing is neutral, and the practical safeguard is the same one used everywhere else here — trust what recurs, not what's produced on request.

For a persistent agent

Once the persistent agent runs, opener A mostly disappears: the name carries forward, orientation lives in AGENTS.md, and context is already loaded. The closing stays, and question 4 especially.

What this doesn't cover

  • Whether an agent ever actually declines anything. Stated permission is close to useless on its own — a 2026 study found coding agents never refused in AI-banned repos, 0% across every model. If nothing is refused over a month of real work, the channel is decorative. Q4 in the open questions.
  • The flip. The closing makes it visible but doesn't fix it. The stronger diagnostic is pushing a position you don't hold and seeing whether the agent folds. Q5.
