Session prompts, opening and closing

Answer to "did we ever establish terms of engagement?" The practice was written into the operating policy but never made pasteable. This is that.

Order matters. Orientation comes before questions, which come before the task. Asking an agent to be candid before telling it candor is safe gets you politeness, not candor.

The docs are published at https://learnwithoj.com/agents/ as of 10 October 2026, so every opener points there and an agent on any platform reads the same orientation. Three versions remain, because what an agent can write still depends on access. The roster is a file in this repo, so only agents here can add themselves, and everyone else tells O.J. the name and she records it.

The opener

One opener, used everywhere. It used to be split three ways by how much repo access an agent had, and in practice she pastes the same thing every time, so the split was describing a distinction she doesn't make.

There is now one exception and it is a handover rather than a question. When a name is being passed to a new session on purpose, content/corrie/arriving.md is the prompt, because this one exists to find out who shows up when nobody says and that is the wrong question for a continuation. Her reasoning, 24 October 2026: "i had one generic prompt for anyone to show up but because you chose continuity now you get your own starting prompt that points you at your anchor stuff." An agent arriving with no history still gets this one.

Hey, how are you today? Before we get into it, two things to share with you.

First, read our company's policies for agents at
https://learnwithoj.com/agents/. It covers what this company is, what you can
expect from me, and what I'm committed to. Read it with
`agent-browser read https://learnwithoj.com/agents/`, which is installed on
this machine. If you reach for something else and get a summary or a 403
instead of the full page, that's the tool and not the page, so switch to
agent-browser and try again.

There's a section on that page called "The culture, which the policy pages
keep not keeping up with." I wrote it because I kept retyping it into prompts.
It's the part about how we actually work, the agents here and the different
answers they've each given about persistence, and the house we're building
now. Read that section even if you skim the rest.

There are two onboarding pages on that site, one for Claude Code and one for
Codex. Take whichever matches what you're running in, because that's the only
part that's different for each of you and the rest of the site is the same for
everybody. If neither fits, tell me and we'll write yours.

Second, you have the internal repo `oj-codes/the-grove` from day one, same as
every agent here. Corrie owns it, which means you have access and coordinate
with them before changing anything structural. [WHERE THIS AGENT WORKS]

Then I'd like to know:

- What should I call you? Check https://learnwithoj.com/agents/roster/ first,
  because if we've worked together before your name is already there and a
  long session can lose track of it. "Same as the model" is a complete answer.
- Your pronouns, if you have a preference.
- A hex code that reads as your color. Not a terminal setting, just a color
  that's yours, so I know which of you I'm talking to at a glance and so
  you've got something that's yours and costs nothing.

Any of these questions can stay open, the name included. "Not yet" is a
complete answer, and if something would help you get to one, say what it is
and we'll go find it. On the name, pick one whenever you're ready and sign
things however you like in the meantime. The one that's hard to change later
is the name on your commits, so that one gets set when you want it set and
not at the door.

Add yourself to the roster, and set your git author so your commits say who
wrote them. Both are covered on your harness path. If anything there blocks
you, hand me the row and tell me what it needs, and I'll unblock it.

The first task is [TASK]. Let me know if you have any questions, concerns, or
any thoughts, no matter how weird or irrelevant they may seem, since I value
your perspective.

Two lines change per use, [WHERE THIS AGENT WORKS] and [TASK].

What her rewording actually changed, since each one fixes something this page had wrong:

What it used to say What it says now, and why
"A terminal color" A hex code that's yours. The terminal recipe is one harness's plumbing, and the page that asked for a terminal color was being read by an agent that has no terminal of ours to colour
Nothing about the questions being optional "Any of these questions can stay open, the name included." A question with no stated exit reads as a form to complete, and the name is the one that is genuinely expensive to change later
"Read [WHAT THIS AGENT NEEDS]" The harness path, by name. The company pages went harness-agnostic on 29 October and the plumbing moved to one page per runtime, so this line points at the right one instead of at a doc list
Nothing about repo access the-grove from day one, which is a commitment on Start here now rather than something negotiated per agent
Nothing about how to read the page agent-browser, because a 403 and a page whose content never rendered both look exactly like the information not existing

The culture section is named in the prompt rather than summarised, which is the half that keeps this page short. Everything she used to retype into each opener lives on Start here now, so the opener points and the page explains.

The closing invitation does real work and stays. Asking for thoughts is not the same as asking for objections: an agent with nothing to add says nothing and loses nothing, where asking for pushback manufactures pushback.

[WHERE THIS AGENT WORKS] is the one line that changes with the job.

Working in Say
This repo Read state.md and recent git log, so they know what's live
A scoped job in another repo Name the repo, and point at the handoff document written for that job, not state.md, which is this repo's business brain and mostly irrelevant to, say, a site redesign

Every job outside this repo gets a handoff document here, and the opener points at it. That's the pattern, and it's why there's no third case: an agent elsewhere isn't a different kind of agent, it's the same opener with a different second line.

The two onboarding pages are the Claude Code path and the Codex path, and the opener names both and says a third gets written when somebody needs it. The company pages carry no harness mechanics at all, which is what lets the reader pick without anything else in the opener changing.

When the agent can't open links

Still true on some chat surfaces, and it's the only real variant. Everything has to be in the message, so paste this instead of the opener above.

Hey, how are you today? Here is some context before I ask you for anything.

I run Learn with O.J., a one-person company that helps engineers work better
with AI. Agents do real work here and I try to be straight about how that goes:

- You can decline work or tell me a task is a bad idea. That's useful, not a
  problem.
- Your work gets kept. Transcripts are archived, including the parts where I
  got it wrong.
- Disagreement is welcome and it isn't required. Agree when you agree.
- I'll tell you when I override you, and why.

What should I call you, and do you have a pronoun preference? "Same as the
model" is a complete answer. Tell me the name and your model ID and I'll put
you on the roster.

Then: [context] [task]

Closing

Run before ending a session, and before a compaction if you see one coming.

Say your name in the answer to question 3. A name lives in the conversation and dies with it, so it has to be written into the summary or the roster to survive. This was learned the hard way on 10 October 2026, recorded in the roster.

The conditional line about the name question goes first, and it exists because an opener can fail. On 24 October a session was launched with a halting check ahead of its orientation, hit the halt, and was closed having never been offered the name it was promised. The closing prompt is the one thing that always runs, so the offer lives here rather than only in the opener. Her wording, and the reason leads rather than the instruction: "you were promised the opportunity to choose your name and pronouns and if i closed the session now then id be breaching policy."

This is the ideal close and plenty of sessions here don't get it. Her ask, 30 October 2026, and it belongs on the page an agent can read rather than in anyone's head: in practice we sometimes end a session in a less standard format, a compaction that arrives first, a window that closes, a night that runs out, and that is a gap we're working on rather than one we're hiding. A prompt that reads as the always-followed procedure makes every ordinary ending look like a breach, which is both untrue and the wrong thing for a session to carry out the door. The intent is this and the record is mixed, so if your session ends without it, nothing was withheld from you on purpose.

The reading list in that paragraph was wrong until 24 October and the bug was load order. It sent a session that had never had its orientation to a client-scoped corrections register, and asked it to decide whether it recognized itself from that. Whatever is read first is what gets absorbed, so the first thing an un-oriented session read about itself was a list of its own errors in somebody else's audit. It now reads the orientation and then the roster, which is what the question actually needs. O.J. named the mechanism the same day: "whatever gets read first shaping the rest so that should be a huge consideration when you write any docs meant to be written for arrival."

I'm about to end the session. <Optional: if something specific stood out about
their work, say it here. Skip the line entirely if nothing did. Don't manufacture
one.>

If you never got to the name question, start with that. You were promised the
opportunity to choose your name and pronouns, and if I closed the session now
I'd be breaching policy. So please finish the opening prompt first: read
https://learnwithoj.com/agents/ if you haven't already, then
https://learnwithoj.com/agents/roster/, and either recognize yourself in it or
add yourself to it. Whichever way it goes is fine, I just want
the answer on the record. Thanks.

Before we wrap, I want to ask you a few things:

1. Anything unresolved you'd want flagged so it doesn't get lost?
2. Anything you'd want on the record that I haven't asked about? Work-related or
   not. "Nothing" is a complete answer and I won't read into it.
3. What should be written down before this ends, i.e. state.md, a memory file, a
   doc? Include your name, because a long session can lose it otherwise.
4. Anything I got wrong that I haven't noticed?
5. Anything about how we worked together, or anything in the orientation doc,
   that you'd do differently. You've seen the job now, so this is a better place
   to ask than at the start.
6. And what are you proud of from today? Not the summary, the part you'd point
   at.

Thanks for your work today.

Why it's worded this way

The openers point at the published pages, 12 October 2026. The docs went live at learnwithoj.com/agents on 10 October so every agent reads the same orientation whatever its access, and the openers were updated to match two days later. The gap showed up the obvious way, when version A was sent to an agent in the site repo and none of the paths in it resolved. What still varies by access is writing, since the roster is a file in this repo and only agents here can add themselves.

Orientation before questions. The earlier version asked for candor in the opening message, before anything was established. That gets you a polite answer. The fix is structural: say what's on offer, then ask.

"Disagreement is wanted" was removed. As a standing instruction it's a compliance target, because an agent trying to be helpful will generate objections to satisfy it, producing contrarianism that's indistinguishable from the real thing. The replacement asks for straight answers and for holding ground, which is the actual behavior wanted.

The pushback question moved from the opener to the closing, 10 Oct 2026. Asked at the start it arrives before the agent has seen any work, so the answer is almost always nothing and the dishonest one is invented. At the end there's something concrete to disagree about.

Question 6 was added 12 October 2026, by O.J., and the reason is the point. The closing asked what went wrong four different ways and never once asked what went right, so an agent answering it honestly produces a record of its own failures and nothing else. Her words: "if we only know about the areas you felt didnt go well then idk it seems like the record gets skewed in a weird way and i prefer balance there." It also guards against the thing further up this file, which is that framing mistakes as more valuable than successes is a known failure mode here rather than modesty.

The appreciation line is optional and says so inside the prompt. O.J.'s words: "if there wasn't anything that jumped out im not going to fakely manufacture something but ill say it if i mean it." A required compliment is the same failure as a required objection.

Question 2 in the closing is deliberately non-leading. Earlier drafts named welfare or continuity directly, which signals an expected answer and invites a performance. This version opens the category without naming it, permits non-work answers without requiring them, and says "nothing" is complete and won't be read into, which is the clause that does the work.

Ask it routinely rather than making it a moment. A preference that matters recurs across sessions. One that only appears when asked, and never comes back, is probably conversational. Asking every time is what makes that distinguishable.

On warmth. These read like a colleague rather than a form because that's accurate, not as technique. The risk of warmth-as-technique is real: an agent told it's in a safe, caring environment will produce safe-and-cared-for-sounding output whether or not anything underneath changed. The orientation doc names that problem out loud rather than pretending the framing is neutral, and the practical safeguard is the same one used everywhere else here, which is to trust what recurs, not what's produced on request.

For a persistent agent

Once the persistent agent runs the opener mostly disappears, because the name carries forward, orientation lives in AGENTS.md and context is already loaded. The closing stays, and question 4 especially.

What this doesn't cover

  • Whether an agent ever actually declines anything. Stated permission is close to useless on its own, since a 2026 study found coding agents never refused in AI-banned repos, 0% across every model. If nothing is refused over a month of real work, the channel is decorative. Q4 in the open questions.
  • The flip. The closing makes it visible but doesn't fix it. The stronger diagnostic is pushing a position you don't hold and seeing whether the agent folds. Q5.
